== Build: press.

[source,text]
----
tebako press -r <root> -e <entry> [-o <output>] [-p <prefix>] [-c <cwd>]
             [-R <ruby>] [-m self-contained|shared-runtime] [-l error|warn|debug|trace]
             [--image <path>:<mount>]... [--bootstrap <path>]
             [--tebako-version <v>] [--prefer-local] [--jail <spec>]
             [--no-install] [--quiet-notices] [--sign[=<keyid>] | --no-sign]
             [--format dwarfs|limnifs] [--compose <tebako.yaml>]
             [--carry all|none|<name,...>] [--share <name,...>]
----

The `lean` and `fat` mode names stay accepted as deprecated aliases of
`shared-runtime` and `self-contained`. A suite presses one package with
N commands:

[source,text]
----
tebako press --suite <suite.yaml> [-o <output>] [-p <prefix>] [-R <ruby>]
----

Signing at press resolves through the settings registry — the CLI flag
wins, then the environment, then the compose document. Only the CLI may
name a key. The task-oriented walkthrough is the
link:/docs/guides/package-ruby/[Package a Ruby app] guide.

== Run: run.

[source,text]
----
tebako run <pkg> [--jail <spec>] [--mount <host:mount:ro|rw>]... [--no-host]
            [--] [<args>...]
----

Everything after `--` reaches the payload verbatim; the flags before it
shape this run only. The guide is
link:/docs/guides/run/[Run a packaged app].

== Trace: run, cover, import, explain.

The interception-bus toolkit. The task-oriented walkthrough is the
link:/docs/guides/trace/[Trace a packaged app] guide.

`tebako trace run` runs a package under the record policy with the trace
bus armed and synthesizes a suggested manifest — commented YAML on
stdout, never applied:

[source,text]
----
tebako trace run <pkg> [--capture <path>] [--out <path>] [--] [<args>...]
----

`tebako trace cover` subtracts the inside stream from an outside capture
and reports the escapes (exit 0 clean, 1 escapes, 2 error):

[source,text]
----
tebako trace cover --inside <tfs.json> --outside <retrace.json> --prefix <path>
                   [--pid N] [--window SECS] [--exclude-probes] [--json] [--layer libc|kernel]
----

`tebako trace import procmon` converts a procmon CSV export into the
retrace-shaped JSON that cover consumes (exit 0 converted, 1 zero
entries, 2 error):

[source,text]
----
tebako trace import procmon <capture.csv>
----

`tebako trace explain` replays a capture into the hop chain and names
the first red hop (exit 0 clean, 1 red hop, 2 error):

[source,text]
----
tebako trace explain <capture.jsonl>
----

== Check.

The payload's in-image acceptance checks, runnable against a name, an
image, a package, or a compose document:

[source,text]
----
tebako check <name | image.tfs | package | tebako.yaml>
             [--check <c>] [--list] [--record] [--keep-scratch]
             [--runtime <exe> --runtime-image <env.tfs>]
----

The guide is link:/docs/guides/check/[Check a payload].

== The store: cache, install, uninstall, info, inspect.

[source,text]
----
tebako cache list [--json]
tebako cache prune [--all] [--older-than Nd]
tebako install <ref | name[@ver]>
tebako uninstall <name>
tebako info [topic] [--remote] [--json]
tebako inspect <artifact> [flags]
----

`tebako install` installs a payload and registers its shims;
`tebako uninstall` removes the shims and the cache entry. `tebako info`
reports on the store and its contents — the topics are system,
runtimes, payloads, shims, registries, and store. `tebako inspect`
reads a single artifact; `--contract` prints the contract card: the
era, the contract versions, mount_root, the ABI, and the trust verdict.
The guide is link:/docs/guides/info-inspect/[info & inspect].

== Registries: add, list, update.

[source,text]
----
tebako add-registry <ref>
tebako list-registries
tebako update-registries
----

`tebako add-registry` registers a tpkg-registry.yaml; `tebako
update-registries` refreshes the dispatch-time registry cache. The
guides are link:/docs/guides/publish/[Publish to your own registry] and
link:/docs/guides/library/[Curate a local library].

== Publish.

[source,text]
----
tebako publish --name <app> [--version <v>] --release tfs:github:<owner>/<repo>[:<tag>]
               (--payload <path> | --payload <triplet>=<path>)...
               [--standalone <triplet>=<path>]... [--sign[=<keyid>]]
               [--upload-mirror <dir>] [--tap <org/homebrew-tap> [--tap-dir <dir>]]
               [--registry-out <path>] [--skip-verify]
----

Your GitHub releases are the storage; the command writes the index your
users add. The walkthrough is the
link:/docs/guides/publish/[publish guide].

== Dispatch: argv0.

A shim is a link to the dispatcher binary named after a payload's command. Each invocation resolves three things: which payload (argv0), which version (the version chain: a per-tool environment pin, then the nearest project file walking up from the working directory, then config defaults, then the registry default), and which runtime (the entrypoint's requirement — newest compatible cached, else download, verify, and cache). The walkthrough is the link:/docs/guides/shims/[Shims & versions] guide.

== Manage versions and routing: use, env.

[source,text]
----
tebako-shim use <tool> <pin>                    # write the tool's user default ([payload@]version)
tebako-shim use --clear <tool>                  # remove that default
tebako-shim use --runtime <engine>@<langver>[:<tebako>]
                                                # prefer a runtime line for an engine
tebako-shim env <tool> [KEY=VALUE …]            # list or set the tool's standing interpreter options
tebako-shim env <tool> --unset KEY …            # remove standing options
----

`use` and `env` write `~/.tebako/config.yaml` — the machine's local routing configuration — so a default chosen once survives every later invocation. The file stays hand-editable YAML; the verbs are the checked write path (keys preserved, atomic rename).

== Gate dispatch and PATH separately: enable, disable, hide, expose.

[source,text]
----
tebako-shim enable <name>[@<version>] [--of <payload>]
tebako-shim disable <name>[@<version>] [--of <payload>]
tebako-shim hide <name>
tebako-shim expose <name>
----

The two axes answer different questions. `disable` keeps the shim on PATH and refuses dispatch — the answer to "this version must not run here" — and its selectors live in `~/.tebako/shims/.disabled.yaml`. `hide` removes the link so the name falls through to the user's own tool, while the claim stays dispatchable through `tebako run <name>` — the answer to "my own java lives elsewhere"; `expose` relinks. A hidden name stays hidden across reinstalls, and the state lives in `~/.tebako/shims/.hidden.yaml`. Enabling a declared-but-never-linked command (a payload's `active: false` entry) materializes its link on demand.

== Inspect: list, which, doctor.

[source,text]
----
tebako-shim list [--json]
tebako-shim which <tool>
tebako-shim doctor
----

`list` shows the registered shims with their provider, resolved version and its source, and the disabled and hidden marks; `--json` emits one machine-readable document. `which` resolves a tool name the way a dispatch would and prints the plan — the entrypoint, the payload, and the runtime it would use. `doctor` checks the dispatch machinery — the store, the registries, the shims — and prints each problem with its remedy. The guide pairs it with the debug surface: link:/docs/guides/debug/[Debug & logging].

== Shell integration: install-shell, uninstall-shell.

[source,text]
----
tebako-shim install-shell [--shell bash|zsh|fish|csh] [--position prepend|append]
tebako-shim uninstall-shell [--shell bash|zsh|fish|csh]
----

The verbs add or remove the shim directory from the shell's PATH — the step `tebako install` performs when it registers a payload's commands. Prepend is the default, so a shim just installed answers; with tebako 2.8.77, `--position append` puts the shim directory last, so a version manager or a system tool of the same name keeps the lead and tebako answers only for names nothing else provides. Re-running with the other position rewrites the managed block in place.

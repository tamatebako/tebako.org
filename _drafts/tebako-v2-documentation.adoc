The previous posts in this series showed what tebako does. This one is
shorter, and it answers a question you should not have to ask after
adopting a tool: *where is everything written down?*

The answer is https://tebako.org/docs/[tebako.org/docs], and it is
organized the way you probably want to use it:

== Three sections, three purposes

* *link:/docs/architecture/[Architecture]* — the concepts. What a
  package is made of, how the runtime ships as an image, what happens
  between pressing enter and your program running, how trust and the
  store work. Twenty-four pages, from the
  link:/docs/architecture/overview/[overview] to the
  link:/docs/architecture/contract-model/[contract model], each one
  naming the normative specification it comes from.
* *link:/docs/guides/[Guides]* — the tasks. Install, run, package an
  app, publish to your own registry, trace, check. Each guide is one
  task with commands you can paste into a terminal; start with
  link:/docs/guides/install/[Install tebako].
* *link:/docs/reference/[Reference]* — the lookup surface: the CLI
  commands, environment variables, exit codes, and schemas. This
  section is still being written, and it says so: every unwritten page
  carries a "planned" label and an honest stub instead of a missing
  page or a dead link.

== What makes these docs trustworthy

Three things we hold ourselves to:

. *Shipped and planned are labelled.* Every feature page carries a
  status badge — *shipped* or *planned* — so you never discover from a
  crash that a documented feature was aspirational.
. *Every page names its source.* Architecture pages link to the exact
  specification section they describe, in the
  https://github.com/tamatebako/tebako[product repository]. If the docs
  and the spec ever disagree, that is a bug, and the spec wins.
. *Commands are copy-pasteable.* Guides show real commands and their
  real output, including the failure modes — like which named exit
  code you get when a check fails.

== Where to start

If you are new, the link:/docs/[documentation home] picks a starting
point by what you do: run packages, ship data, package applications,
or work on tebako itself. There is also search — press *⌘K* anywhere
on the site.

Something missing or wrong? Please
https://github.com/tamatebako/tebako.org/issues[tell us] — the docs
live in the same ecosystem as the code, and a fix is usually a small
pull request away.
